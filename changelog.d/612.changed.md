`STATUS.md` records the concurrency shape of every candidate axis in the Rust kernels before any thread pool is added: the item count at the declared scale against the core count, and whether an item ever waits. `tokio` is declined on that shape rather than on being an I/O runtime — it carries M:N lightweight tasks, but every item is CPU-saturating with no await point, so achieved parallelism is the worker count a plain pool already gives. The heat-bath sweep and Dinic's maximum flow are not candidates for any pool: parallelising them changes what they compute.
