The two-channel count emission takes one covariate per channel, and every seam
above it passes one — including the Rust backend (#658).

**The families.** #631 refused a covariate on a pair family because "the two
channels would each need their own — an exposure for the total, a trial count
for the successes — and one tensor cannot be both". It can, with the channel
axis the observation already has: `(..., 2)`, splitting where the observation
splits. A covariate without that axis is still refused. **The neutral covariate
is not ones**: it is ones for the total, whose exposure multiplies a rate, and
the family's own declared `trials` for the successes, whose covariate replaces a
trial count — ones on both asks a beta-binomial for more successes than trials
and scores `-inf`.

**The seams.** `external_field` and `marginal_log_likelihood_torch` scored
without one. `external_field` was a defect rather than deferred work:
`fit_spatio_sequential` passes it a posterior computed *with* the covariate
while its own `log_density` scored *without*, so the two halves of one step
disagreed about the model — monotone either way, which is why nothing failed.
`covariate_block` is the one slice all three share, and it adds the trailing
singleton only where the covariate carries no axes of its own.

**The Rust backend.** The kernel tabulated `log p(count | class, state)` and
indexed by the count; under a covariate the density is a function of the count
*and* what it is scored against, so no table indexed by the count alone exists.
The kernel never knew what the index meant, only that the table was built from
it, so the caller tabulates the distinct `(count, covariate)` pairs and hands
the row each observation falls in. `src/coupled.rs` changes in one way only:
the index widens from `u16` to `u32`, since a row is no longer bounded by the
largest count. Without a covariate the rows *are* the counts and the table is
count-major — the same numbers as before, asserted on the arrays.

At the ci instance the tabulation finds 9,989 and 245 rows against 64,000
observations, so a per-vertex exposure repeated down the positions stays a
table rather than becoming a per-observation score array. Agreement with the
NumPy oracle under a covariate: 2.7e-15 relative on the evidence, 2.9e-15 on
the field, 1.0e-09 absolute on the posteriors, one thread.
