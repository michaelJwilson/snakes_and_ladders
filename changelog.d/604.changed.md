Every `oxi_snakes_and_ladders` kernel releases the GIL (#604) -- nine of the
ten `#[pyfunction]`s, `double` being a placeholder integer multiply. Each
extracts its slices and then touches no Python object, so the work runs
inside `Python::detach`. No arithmetic and no serial timing moves; what
changes is that `snakes_and_ladders.parallel`'s `backend="threads"` has
eligible sites for the first time. Four Python threads on the Potts sweep,
32x32, took 3.82x the wall of one before and 1.08x after -- throughput 1.05x
against 3.70x, beside a NumPy control at 3.19x.
