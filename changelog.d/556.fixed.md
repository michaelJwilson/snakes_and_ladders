On a host sharing one `.venv` across many worktrees, a bare import no longer resolves to whichever worktree installed last. The shared environment carries dependencies and not the project, so `PYTHONPATH` is the only route to the package and there is no global editable path for a script to repoint: a missing `PYTHONPATH` now raises `ModuleNotFoundError` instead of silently running a stranger's half-finished branch. Every `infra/*.sh` exports it from its own location, so a script operates on the tree it lives in rather than on whatever the environment last pointed at, and `infra/ledgers.sh` passes `--no-sync` so it cannot re-sync an environment 52 worktrees share. `infra/new_worktree.sh` copies a compiled extension only when it is newer than every `src/*.rs` and builds one otherwise — at filing 121 of 154 extensions across the worktrees predated the newest source, and a stale one imports cleanly and fails only when something calls the changed signature. Three guards report an incomplete or foreign environment as an environment fault rather than letting it surface as a failure in an unrelated test, and `infra/repair_environment.py` restores one additively: it installs the declared requirements that are absent and names nothing else, so the repair cannot repoint the editable path the other worktrees follow the way `uv sync --all-extras` would.
