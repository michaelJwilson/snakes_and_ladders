Every test module carries a marker, and "unmarked" stops being a state
(#622 step 4). It was one state meaning two things: the module exercises shared
machinery and has no problem to name, or the scan failed to see what it
exercises. An axis with a hole in it read exactly like a complete one.

A module with no problem now carries `infra`, added at collection like the
problem markers and never by an author. **It is a claim, not a default**:
`tests/regression/test_problem_markers.py` asserts that no module carrying it
imports any code `PROBLEMS.md` attributes to a problem, so the two readings of
the source — the scan and the catalogue — cannot disagree silently. Today 190
of 263 modules carry a problem and 73 carry `infra`, and none of the 73 reaches
defining code.

`infra` is a third axis, beside the kind and the tier: a module is `infra`
*and* an oracle test, as it is `critical` *and* an oracle test. `infra/gates.py`
registers it and `infra/test_kinds.py` names it, so the marker `pytest` accepts
and the marker the guards read stay one definition.

measured before the catalogue derivation landed and is replaced by the numbers
above. `-m potts_lattice` names 59 modules against the 23 it named then.
