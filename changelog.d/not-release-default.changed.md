`release` is deselected by default. `pyproject.toml`'s `addopts` carries `-m "not release"`, so a bare `pytest` runs the tier a pull request is judged on rather than one with no upper bound on its duration, and reaching the long tier is a deliberate flag instead of a matter of remembering one. `infra/release.sh` overrides it with `-m "release or not release"` — a tautology written out rather than an empty `-m ""`, so a later reader can see what it selects and does not delete it as a stray flag. `infra/gates.py` carries that expression as the release gate's, beside the `critical` and `not release` the other two gates use, and `tests/regression/test_gates.py` holds the default equal to the main gate's: the failure this guards is silent, since the release gate ran a bare `pytest` to mean every tier and a default filter turns that into the per-PR tier without erroring. Measured on the tree: 2,291 of 2,356 tests by default, 2,356 under the release expression, and `-m critical` unchanged at 187 because a marker argument replaces the default rather than intersecting with it.
