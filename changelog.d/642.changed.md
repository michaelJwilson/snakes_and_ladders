`FlowNetwork` keeps the contiguous form it already built (#642). `from_arcs`
assembled the compiled consumer's arrays on its way to the list store and then
discarded them, so a network built from arcs and solved in Rust made the round
trip NumPy → list → NumPy for nothing. `as_arrays` is **289 ns** against
**2.87 ms** at 20,000 edges, and one alpha-expansion sweep of four labels
through the Rust backend is **1.240x** at 16x16 and **1.112x** at 32x32. The
Python backend, which never calls `as_arrays`, is the control at 1.000x. The
returned arrays are bit-identical whether kept or derived, and `add_edge` and
`max_flow` both drop the form, since a kept form outliving its store would be a
worse defect than the derivation it replaces.

The list-of-lists store stays, on #586's measurement: a row is 1.95 ms as
lists, 3.93 ms flat with offsets and 25.63 ms as a NumPy slice over 16,384 rows
of degree six, because Dinic is a pure-Python inner loop.

The survey no longer reports a per-call derivation against a **constructor**.
"Derives X per call" names a cost that repeats on one object — an accessor
asked twice pays twice, and storing the result removes the second payment. A
`classmethod` that builds an instance runs once per instance, so there is no
second payment to remove and no rewrite that clears the finding short of
deleting the constructor. `FlowNetwork.from_arcs` carried it while the survey's
own next line recorded the measurement keeping the store it objected to, which
read as the survey contradicting itself about one class.
`tests/regression/test_structure_survey.py` holds that narrowing to a paired
control: an accessor over a non-compressed store is still reported, the same
derivation in a constructor is not.
