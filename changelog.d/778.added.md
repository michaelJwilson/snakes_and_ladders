`snakes_and_ladders.track` is the one seam a run reports through, and its store is Aim's own: `Run` is a `runtime_checkable` Protocol of `track`, `__setitem__` and `close`, written with `aim.Run`'s signatures, so an `aim.Run` is passed in with no adapter (`isinstance` asserted by a `release` test). `track(run=None, metrics=None, **params)` binds a `TrackedOptimization` to a `contextvars.ContextVar` for the block, `current()` reads it, and `NULL` --- the default outside any block, holding the shared `NULL_RUN` --- makes `record` return on its first line. `opt.fit.fit`, `opt.hmc.sample`, `opt.hmc.anneal`, `opt.hmc.parallel_tempering`, `search.potts_mcmc.anneal_potts`, `search.potts_mcmc.parallel_tempering`, `search.tempered`'s two ensembles and `qa.figure.write_qa_figure` call `record` once per iteration, sweep, round or figure. Every number recorded is one its result dataclass already returns, so a series ends at the field, and no default, draw order or return value changes: the untracked run is bitwise what it was. A `Metrics` set says what the state means beside the counters, one per problem class in the module owning its objective or energy --- `PottsMetrics`, `HmmMetrics`, `TreeMetrics`, `MixtureMetrics`, `CodeMetrics`, `TestFunctionMetrics` --- each metric computed by a function the package already has and none defined new; they are evaluated only inside a block. `MemoryRun` keeps the record for a test, keyed by `(name, context)` as Aim keys a sequence, and `as_aim` wraps a figure as an `aim.Image` where `aim` is installed --- the optional `track` extra, which no CI job syncs and which carries PYSEC-2026-1087 and PYSEC-2026-1088, unfixed against its current release and both in the server `aim up` runs.
