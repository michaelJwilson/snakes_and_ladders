The `search/` and `opt/` packages' twelve public entry points that returned a bare tuple return a frozen dataclass named for what it carries --- `Labelling`, `GroundState`, `PairedArcs`, `MaxCut`, `RungField`, `Bracket`, `CategoricalFit`, `GraphStatistics`, `NearestMinimum` --- each iterating in its old tuple order, so every caller unpacking one is unchanged and every pinned array is the same array (issue #865, the `search/` and `opt/` pull request after `likelihood/`'s).
