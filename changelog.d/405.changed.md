The correctness tiers run distributed. CI's `python-tests` job runs `infra/select_tests.py`'s selection in two invocations: the correctness paths under `pytest -n 3` with `tests/benchmarks` ignored and the coverage gate unchanged, then the selection's benchmark paths serially. `pytest-xdist` (MIT, 1.9k stars) joins the `test` extra. Measured under issue #525 and not re-run: 993.7 s at `n = 1` against 361.9 s at `n = 3` on the CI tier, like-for-like with benchmarks off on both sides, 2.75x; one to four workers gave 1.00x, 1.89x, 2.30x and 2.25x, so three is the peak. Every cell returned the same 2,302 passed and 13 skipped.

Benchmarks are never distributed, and two guards in `tests/conftest.py` say so by failing. `pytest-benchmark` disables itself whenever a run is distributed, without failing and without a line anyone reads, so `-n` over the whole tree would report its 212 benchmark tests as passed having timed none of them; a benchmark that reaches a distributed run now fails at setup, naming the reason. The duration cap is the same defect again — `SAL_DURATION_CAP` and `SAL_KEY_DURATION_CAP` are read on the controller while the durations are recorded in the workers, so every test would pass every cap — and a capped run under `-n` now fails too. `infra/validate.sh`, which sets both caps, and `infra/measure_test_budget.sh`, which measures the budgets, stay serial.
