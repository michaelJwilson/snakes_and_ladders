# Problems

The problems this repository supports, one row each, with the code that simulates, evaluates, fits, searches and learns on it. Every cell is a symbol or a path that exists in the tree; `tests/regression/test_problems_catalogue.py` resolves each one, so a row cannot outlive what it names. `STATUS.md` says how far each has got; `CHECKS.md`, written by `infra/ledgers.sh` and not committed, lists the checks each rests on. `infra/problems_tables.py` reads this table and writes the two applicability tables the textbook typesets (`docs/tex/generated/problems_tables.tex`), naming each symbol by the algorithm or oracle it is; a symbol it cannot name fails the generation. The tables are written at build time and not committed (issue #425); `tests/regression/docs/test_problems_tables.py` holds what the generator writes to what the textbook needs.

An **oracle** is the independent answer an evaluator is pinned to: an enumeration, a brute-force sum, or a closed form that shares no code with the thing it checks.

A **fixture** is the instance itself, declared in one file per problem and tier under `tests/regression/fixtures/` and loaded through `snakes_and_ladders.sim.fixtures.fixture` (issue #382): the size, the seed, the model that reads the file and the oracle available at that size. The tier is the time budget the size was chosen for, per `DEV.md`. Every row names the fixtures its tests, figures and notebooks run on, and `tests/regression/test_fixture_registry.py` holds the two to each other --- a row without a loadable CI-tier fixture, or a fixture no row names, fails.
